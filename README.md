# SoilMoisture Analytics: Soil Moisture Monitoring & Data Analytics Platform

SoilMoisture Analytics is a modern, responsive full-stack web application designed for agricultural research, site analysis, and environmental monitoring. It provides a platform to query soil moisture and environmental metrics for specific dates and coordinates, upload custom datasets with dynamic schema adaptation, and visualize locations interactively on a map.

## Key Features

*   **Interactive Spatial-Temporal Querying**: Search environmental data for any site by combining GPS coordinates (Latitude/Longitude) and a calendar date.
*   **Flexible CSV Batch Processing**: Upload custom soil moisture and environmental CSV files directly from the UI. The backend automatically aligns varied headers (e.g., `temp`, `smap`, `rain`, `long`) to standard formats and imports them.
*   **Dynamic Database Schema Evolution**: When uploading CSV files with custom columns, the database automatically performs schema migrations (`ALTER TABLE`) to adapt to new metrics, ensuring zero data loss and maximum extensibility.
*   **Interactive Leaflet Map**: Fully integrated OpenStreetMap layer that automatically centers and markers the queried location with detailed popup coordinates.
*   **Premium Glassmorphism User Interface**: Designed with modern aesthetics, vibrant indicators, glass card panels, smooth hover transitions, and custom-styled metrics cards with dynamic iconography (Lucide icons).

## Architecture Overview

The system follows a classic decoupled client-server architecture:

```
  ┌──────────────────────────────────────────────────────────┐
  │                   React Frontend (3000)                  │
  │  (Dashboard UI, Leaflet Map, File Upload, Lucide Icons)   │
  └────────────────────────────┬─────────────────────────────┘
                               │
                        REST HTTP Requests
                               │
                               ▼
  ┌──────────────────────────────────────────────────────────┐
  │                    Flask Backend (5000)                  │
  │     (Data Routing, CSV Mapping, Schema Evolution, CORS)   │
  └────────────────────────────┬─────────────────────────────┘
                               │
                        Local SQL Queries
                               │
                               ▼
  ┌──────────────────────────────────────────────────────────┐
  │              SQLite Database (soil_moisture.db)           │
  │           (soil_data table with indexed columns)         │
  └──────────────────────────────────────────────────────────┘
```

*   **Frontend**: React (Single Page Application) styled using native CSS variables, utilizing Axios for API calls and React-Leaflet for mapping.
*   **Backend**: Flask application running on port 5000. It uses Pandas for CSV ingestion/manipulation and connects natively to a local SQLite instance.
*   **Database**: SQLite (`soil_moisture.db`) storing the `soil_data` table. Optimized with database indexes to support rapid spatial-temporal querying.

## Component Breakdown

### 1. Data Seeding & Migration (`migrate_data.py`)
This script acts as the initial ETL pipeline to import CSV data into the local SQLite database.
*   **Source Data**: Reads from `fusion_training_table_2021_2024_normalized.csv` (the standardized multi-year dataset generated by the data preparation pipeline under `multisource_fusion/`).
*   **Normalization**: Standardizes all incoming column headers to lowercase.
*   **Geospatial Defaults**: If coordinates are missing, it appends default coordinates (latitude: `36.1156071`, longitude: `-97.0583681`) to align with the default sensor location.
*   **Database Seeding**: Creates/replaces the table `soil_data` in `backend/soil_moisture.db`.
*   **Performance Optimization**: Automatically creates a composite index `idx_date_lat_lon` on the `(date, latitude, longitude)` columns, ensuring sub-millisecond queries.

### 2. Flask REST API Backend (`backend/app.py`)
Runs the REST API endpoints and handles internal logic:
*   **Search Endpoint (`/api/search`)**:
    *   Accepts a mandatory `date` query param, and optional `lat` and `lon`.
    *   Queries the local SQLite database with a tolerance of **`±0.05` degrees** in latitude and longitude coordinates to account for small GPS variations.
    *   Returns matching records from the database for the specified date and location.
*   **Batch Uploader Endpoint (`/api/upload`)**:
    *   Accepts raw multipart-form CSV uploads.
    *   Contains a mapping dictionary to clean and translate various column name variations into uniform SQL database columns.
    *   Automatically formats various date patterns into `YYYY-MM-DD`.
    *   Interrogates the SQLite table schema and dynamically executes `ALTER TABLE` to append any non-standard custom columns included in the CSV.

### 3. React Dashboard Frontend (`frontend/src/App.js`)
The user-facing dashboard orchestrating interaction:
*   **Recenter View (`ChangeView`)**: A React-Leaflet helper component that dynamically translates and pans the viewport when coordinates change.
*   **State Management**: Tracks search parameters, query status, file upload queues, visual alerts, and environmental state records.
*   **Environmental Metric Cards**: Display grid containing custom cards displaying various soil moisture and environmental metrics from the database, including soil moisture, temperature, precipitation, NDVI, and other sensor data.

### 4. Modern Styling (`frontend/src/App.css`)
Contains the styling system supporting the application:
*   **CSS Custom Variables**: Centralized color tokens for easy customization.
*   **Modern Layouts**: Clean card-based UI with smooth transitions and responsive design.
*   **Interactive Elements**: Hover effects and dynamic styling for better user experience.

## Research Code: ESSD Ensemble & Multi-Source Fusion

[ESSD Ensemble and Multi-Source Fusion Research](file:///c:/Users/vinay/OneDrive/Desktop/mp2/essd_ensemble/) represents the scientific core of the SoilMoisture Analytics platform. Rather than detailing these modeling steps inside a static report, all preprocessing, model training, cross-validation, and analysis pipelines are fully documented in the following interactive Jupyter notebooks.

### 1. ESSD Paper Ensemble Modeling (`essd_ensemble/`)
The [essd_ensemble/](file:///c:/Users/vinay/OneDrive/Desktop/mp2/essd_ensemble/) directory contains the multi-satellite ensemble modeling pipeline.

*   **Core Notebook**: [major_project _essd.ipynb](file:///c:/Users/vinay/OneDrive/Desktop/mp2/essd_ensemble/major_project%20_essd.ipynb)
*   **Multi-Satellite Features**: Integrates data from multiple satellite constellations to map and model high-resolution soil moisture:
    *   **Sentinel-1 SAR**: Dual-polarization backscatter parameters (`VV_soil`, `VH_soil`).
    *   **Sentinel-2 Optical/NIR**: Spectral bands (B1–B12, B8A) and vegetation indices (`NDVI`, `NDMI`).
    *   **Landsat**: Optical/thermal bands and derived vegetation indices (`landsat_NDVI`, `landsat_NDMI`).
    *   **Spatial Coordinates**: Spatial positioning inputs (`latitude`, `longitude`).
*   **Model Architectures**:
    *   **Random Forest Regressor**: Trained using 5-Fold Cross Validation.
    *   **TabNet Regressor**: A deep learning model designed for tabular data (using PyTorch TabNet) trained using K-Fold Cross Validation.
    *   **XGBoost Regressor**: Optimized via grid search hyperparameter tuning (`GridSearchCV`).
*   **Weight Optimization (Optuna)**: Uses Optuna to find the optimal weighted combination of Random Forest, TabNet, and XGBoost predictions. This optimization is performed on an ensemble validation split separate from the test set to prevent validation leakage.
*   **Evaluation & Diagnostics**:
    *   Computes performance metrics: R², Bias, RMSE, ubRMSE (unbiased RMSE), and Pearson correlation.
    *   Generates a 1:1 density scatter plot with Gaussian Kernel Density Estimation (KDE) color-mapping to display observation-prediction density distributions.
    *   Plots Optuna's trial weight evolution trajectory.
*   **Saved Models**: The trained models are saved under the `models/` subdirectory, including the Random Forest model (`rf_model.pkl`), the XGBoost model (`xgb_model.pkl`), and the TabNet model & scaler (`tabnet_model.zip`, `tabnet_target_scaler.pkl`).

### 2. Multi-Source Fusion Research & Analysis (`multisource_fusion/`)
The [multisource_fusion/](file:///c:/Users/vinay/OneDrive/Desktop/mp2/multisource_fusion/) directory contains the data preparation pipelines, datasets, training results, and feature analysis code.

#### A. Data Preparation Pipeline
*   **Notebook**: [data_preparation.ipynb](file:///c:/Users/vinay/OneDrive/Desktop/mp2/multisource_fusion/data_preparation.ipynb)
*   **Pipeline Processing Steps**:
    1.  **ERA5 Meteorology Ingestion**: Extracts daily meteorological parameters, converts precipitation from meters to mm, converts temperature from Kelvin to Celsius, and creates lag/rolling window features (`P_lag1`, `P_lag2`, `P_lag3`, 7-day rolling `P_7day`).
    2.  **Sentinel-2 Ingestion**: Renames columns (`NDVI_S2`, `NDMI_S2`), groups duplicate dates by average value, and applies linear interpolation to resolve missing satellite observation days.
    3.  **ISMN Ground-Truth Ingestion**: Cleans ground-truth station observations (Stillwater 5 WNW station, Oklahoma, Stevens-Hydraprobe-II sensor), filtering out poor observations using quality flags (`qc == "G"`) and aggregating measurements to daily mean ground-truth soil moisture (`SM_ISMN_daily`).
    4.  **SMAP Satellite Ingestion**: Parses SMAP daily `.h5` files, matches spatial coordinates (latitude: `36.1346`, longitude: `-97.1082`), and extracts quality-filtered daily soil moisture (`SM_SMAP`, `SM_SMAP_lag1`).
    5.  **Data Merging & Normalization**: Merges all four sources chronologically, handles missing values using forward/backward fill, and normalizes the features to a `[0, 1]` range using a `MinMaxScaler`.

#### B. Cleaned & Normalized Datasets
*   [fusion_training_table_2020_normalized.csv](file:///c:/Users/vinay/OneDrive/Desktop/mp2/multisource_fusion/fusion_training_table_2020_normalized.csv): Cleaned and normalized daily records for the year 2020 (354 records).
*   [fusion_training_table_2021_2024_normalized.csv](file:///c:/Users/vinay/OneDrive/Desktop/mp2/multisource_fusion/fusion_training_table_2021_2024_normalized.csv): Multi-year cleaned and normalized records for 2021–2024 (1328 records). *Note: This dataset serves as the source file for database seeding (see `migrate_data.py`).*

#### C. Training and Testing Results
*   **2020 Results**: [major_project_SM_2020_results.ipynb](file:///c:/Users/vinay/OneDrive/Desktop/mp2/multisource_fusion/major_project_SM_2020_results.ipynb)
*   **2021–2024 Results**: [majorproject_SM_2021-24_results.ipynb](file:///c:/Users/vinay/OneDrive/Desktop/mp2/multisource_fusion/majorproject_SM_2021-24_results.ipynb)
*   **Modeling Steps**:
    *   Reads the respective normalized dataset, separates features and target (predicting `SM_ISMN_daily`), and splits into an 80/20 train-test ratio.
    *   Trains a baseline **Level 1** Random Forest Regressor using `SM_SMAP` and `SM_SMAP_lag1` features.
    *   Evaluates metrics (R², Bias, RMSE, MAE, Pearson) and visualizes predicted vs. observed scatter plots.

#### D. Exploratory Analysis & Interpretability
*   **Notebook**: [analyis and tables.ipynb](file:///c:/Users/vinay/OneDrive/Desktop/mp2/multisource_fusion/analyis%20and%20tables.ipynb)

## Database Schema & Evolution

The database schema is highly flexible. After initial seeding, the core schema contains standard columns like:
*   `date` (TEXT - indexed)
*   `latitude` (REAL - indexed)
*   `longitude` (REAL - indexed)
*   `SM_ISMN_daily` (REAL)
*   `SM_SMAP` (REAL)
*   `NDMI_S2` (REAL)
*   `NDVI_S2` (REAL)
*   `P_ERA5_daily` (REAL)
*   `T2M_ERA5_daily` (REAL)

### Schema Evolution
When a user uploads a CSV containing unique custom sensors (e.g., `phosphorus_level` or `soil_ph`), the backend executes:
```sql
ALTER TABLE soil_data ADD COLUMN "phosphorus_level" REAL;
```
This enables the database to evolve dynamically without requiring manual migrations, code updates, or service restarts.

## Installation & Setup Guide

### Prerequisites
*   Python 3.8 or higher installed on your computer.
*   Node.js (v16.x or higher) and npm installed.

### Step 1: Database Migration (Seeding)
Before running the servers, you must seed the SQLite database using the provided Python migration script.

1.  Open your terminal in the project's root directory.
2.  Install required Python packages:
    ```bash
    pip install pandas
    ```
3.  Execute the migration script:
    ```bash
    python migrate_data.py
    ```
    *You should see a success message: `Successfully migrated <number> records to backend/soil_moisture.db`.*

### Step 2: Start the Backend Server
1.  Navigate to the `backend` directory:
    ```bash
    cd backend
    ```
2.  (Optional) Create and activate a virtual environment:
    ```bash
    python -m venv venv
    # On Windows:
    .\venv\Scripts\activate
    # On macOS/Linux:
    source venv/bin/activate
    ```
3.  Install backend dependencies:
    ```bash
    pip install flask flask-cors pandas
    ```
4.  Run the Flask application:
    ```bash
    python app.py
    ```
    *The backend server will launch and run locally on `http://127.0.0.1:5000`.*

### Step 3: Start the React Frontend
1.  Open a new terminal window and navigate to the `frontend` directory:
    ```bash
    cd frontend
    ```
2.  Install the required npm dependencies:
    ```bash
    npm install
    ```
3.  Launch the React local development server:
    ```bash
    npm start
    ```
    *This will launch your web browser and open `http://localhost:3000` where you can view and use the dashboard.*

## API Endpoints Reference

### `GET /api/search`
Queries environmental data for a given date and location.

*   **Parameters**:
    *   `date` (Required): String in format `YYYY-MM-DD`
    *   `lat` (Optional): Float coordinate (e.g., `36.1156`)
    *   `lon` (Optional): Float coordinate (e.g., `-97.0583`)

*   **Response (Success)**:
    ```json
    [
      {
        "date": "2023-06-15",
        "latitude": 36.1156,
        "longitude": -97.0583,
        "SM_ISMN_daily": 0.243,
        "SM_SMAP": 0.157,
        "NDVI_S2": 0.500,
        "NDMI_S2": 0.161,
        "P_ERA5_daily": 0.594,
        "T2M_ERA5_daily": 0.149
      }
    ]
    ```

*   **Content-Type**: `multipart/form-data`
*   **Body**:
    *   `file`: The CSV file containing target records.

## CSV File Format Guidelines

To ensure the auto-mapper imports CSV data correctly, structure files with the following requirements:

1.  **Required Fields**:
    *   A column containing dates (headers: `date`, `system:ind date`, etc.).
    *   Latitude and Longitude columns (headers: `lat`, `latitude`, `lon`, `longitude`).

2.  **Supported Column Mappings (Automatic)**:
    The CSV importer will recognize and automatically rename the following headers to standard metrics:

    | Raw CSV Header (Case-Insensitive) | Standardized Target Column |
    | :--- | :--- |
    | `lat`, `latitude` | `latitude` |
    | `lon`, `longitude` | `longitude` |
    | `system:ind date`, `date` | `date` |

3.  **Supported Date Formats**:
    *   `YYYY-MM-DD` (e.g. `2024-05-20`)
    *   `YYYYMMDD` (e.g. `20240520`)
    *   Any standard date format parsable by Pandas' `to_datetime` function.
